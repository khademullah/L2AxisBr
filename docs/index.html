AXI-Stream · Verilator · pcap

Two-port MAC‑learning Ethernet bridge

Learn a source MAC, then flood, forward, or filter. A recorded pcap drives the bench. The SystemVerilog table and the C table have to print the same result.

View the source Run make demo

Learn

A unicast source MAC is installed on the ingress port. Multicast sources are left out of the table.

Flood

An unknown destination, a broadcast, or an I/G multicast leaves on the other port.

Forward or filter

A destination already known on the other port is forwarded. A destination known on this port is filtered.

The gate is mis=0

pkt_l2br and dpi/l2_model.c share one 1024-entry table. Observers sit on the port wires. mis counts a decision, length, or fingerprint that disagrees. byte_mis counts an egress frame that disagrees with the ingress frame that was forwarded.

Both directions of ns1_iperf.pcap enter port A. The first frame floods. Both MACs are then known on A, so the rest of that window is filtered.

[BR] rx_a=64  rx_b=0  tx_a=0  tx_b=1  flood=1  fwd=0  filter=63  drop=0  byte_mis=0  mis=0

SPLIT=1 places source 02:00:00:00:00:01 on port A and every other source on port B. After the opening flood, unicast traffic is forwarded.

[BR] rx_a=38  rx_b=26  tx_a=26  tx_b=38  flood=1  fwd=63  filter=0  drop=0  byte_mis=0  mis=0

Later

These ten are in the regression. Each one lands in the SystemVerilog table and the C table, and mis=0 stays the gate. STP, LAG, and QinQ stay out.

  1. Aging. Supported. AGE=N expires an entry after N clocks. The next unicast to that MAC floods.
  2. Station move in the regression. Supported. A source learned on A and then seen on B is updated, and make ci checks the forward.
  3. Both ports in one cycle. Supported. BOTH=1 offers a beat on A and B together.
  4. More than one frame in the ingress buffer. Supported. The next frame can enter while the previous one is still leaving.
  5. Ethernet lengths. Supported. LEN=1 is 64 to 1518. LEN=2 is 64 to 9000. The 12-to-2048 rule stays the default.
  6. One VLAN. Supported. Learn the source with its 802.1Q VID. Flood and filter stay inside that VID.
  7. Slot compare. Supported. Every table entry is checked against the C table.
  8. The whole capture. Supported. make ci replays all 1000 frames of the iperf pcap.
  9. Other widths. Supported. The same pcaps pass at 32, 128, and 256 bits, along with 8 and 64.
  10. A static multicast table. Supported. MCAST=1 installs one group on port B. An unknown group still floods.

Quick start

Linux, Verilator 5.020 or later, and libpcap.

sudo apt update
sudo apt install build-essential verilator libpcap-dev
make demo

The worked capture is iperf3 on two NICs, Ethernet link type 1. Pcap2HDL is the pcap-to-AXIS fixture. L2AxisBr is the device on two of those slave ports. A beat is accepted only when tvalid && tready.
